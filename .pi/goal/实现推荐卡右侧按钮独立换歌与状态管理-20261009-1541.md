# Goal
将首页推荐卡（`_FeaturedHeroCard`）右侧圆形按钮改造为独立的随机换歌刷新按钮，点击时仅更新卡片展示歌曲与推荐批次，不启动、暂停或干扰任何播放器状态；卡片主体点击仍保持播放当前展示歌曲及对应批次。同时完善推荐歌曲 Notifier 的请求代次（generation）防护与同服务端缓存写入顺序，防止异步与切库竞态导致的数据污染。

# Acceptance Criteria
1. **推荐卡独立换歌交互**：
   - 推荐卡右侧圆形按钮提供标识 `Key('daily-recommend-shuffle-button')` 及刷新图标与提示，点击仅触发 `shuffle()` 异步刷新展示。
   - 在播放器处于空闲（idle）、暂停（paused）、正在播放（playing）状态下点击右侧刷新按钮，均不调用播放器的 `setQueue`、`play`、`pause`、`seek` 或切歌等指令，当前播放队列、当前曲目、播放状态与播放进度保持不变。
   - 点击推荐卡主体区域仍正常触发完整播放流程，将当前卡片展示歌曲作为首曲并播放当前推荐批次。

2. **状态与缓存一致性（Notifier）**：
   - `DailyRecommendSongsNotifier` 实现 generation 请求锁与 stale 校验，防止快速重复点击引发并发竞争。
   - 异步换歌获取批次后，若首曲与当前相同且批次包含其他歌曲，将不同 ID 歌曲调整至首位展示。
   - 请求失败、返回空数据或无可用服务端时保留现有卡片与缓存状态，不抛出破坏性错误。
   - 同 `serverId` 缓存写入具备串行化与代次优先机制：较新日期或同日较新 generation 优先生效，数据库等待期间发生切库、重建或销毁时，旧代响应不得向当前 UI 发布失效状态，亦不得覆盖已生效的新缓存。

3. **自动化测试与静态检查**：
   - `test/daily_recommend_shuffle_test.dart` 完整覆盖并发刷新、网络与数据库写入竞态、切库与销毁隔离、空响应及缓存有序性。
   - `test/home_daily_card_widget_test.dart` 完整覆盖空闲/暂停/播放中点击只换歌不播放、主体点击播放当前批次、以及独立按键/键盘激活。
   - 以下静态分析与测试命令全部通过：
     - `dart format --output=none --set-exit-if-changed lib/core/providers.dart lib/features/home/home_screen.dart test/daily_recommend_shuffle_test.dart test/home_daily_card_widget_test.dart`
     - `flutter analyze --no-pub lib/core/providers.dart lib/features/home/home_screen.dart test/daily_recommend_shuffle_test.dart test/home_daily_card_widget_test.dart`
     - `flutter test --no-pub test/daily_recommend_shuffle_test.dart test/home_daily_card_widget_test.dart`

# Boundaries
- 不修改推荐卡下方“随机歌曲”列表项、列表旁刷新按钮、列表播放按钮、底栏迷你播放器及全局播放器逻辑。
- 不变更数据库表结构（schema），不新增迁移脚本，沿用现有 `dailyRecommends` 表与主键机制。
- 不创建新的 Git 分支或 worktree，不切换现有分支。
- 不引入未授权的第三方外部依赖或改动无关业务页面。
